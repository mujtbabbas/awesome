# Reader's Guide — awesome

## What this project is

This is **the original Awesome list** (by Sindre Sorhus): a curated index of
awesome lists about everything — the parent list of the entire "awesome"
ecosystem. Each entry links to a hand-picked list on a topic, and every list
in it is expected to meet the quality bar set by the Awesome Manifesto.

## How the content is organised

- [`readme.md`](readme.md) — the list itself (this guide was written from its
  section outline and the repository tree). After a **Contents** index it is
  split into thematic sections:
  - **Platforms**, **Programming Languages**, **Front-End Development**,
    **Back-End Development**, **Computer Science**, **Big Data**, **Theory**
  - **Books**, **Editors**, **Gaming**, **Development Environment**,
    **Entertainment**, **Databases**, **Media**, **Learn**
  - **Security**, **Content Management Systems**, **Hardware**, **Business**,
    **Work**, **Networking**, **Decentralized Systems**,
    **Health and Social Science**, **Events**, **Testing**, **Miscellaneous**
  - **Related** — meta-resources about the awesome ecosystem itself.
- [`awesome.md`](awesome.md) — **The Awesome Manifesto**: what "awesome"
  means, the curation bar ("a curation, not a collection"), and the official
  Awesome badges.
- [`contributing.md`](contributing.md) and `pull_request_template.md` — how
  lists get added and the checklist a submission must pass.
- [`create-list.md`](create-list.md) — how to start your own awesome list.
- [`code-of-conduct.md`](code-of-conduct.md), `license` (CC0), and `media/` —
  the logo/badge artwork.

## How to use it

1. Open `readme.md`, jump via **Contents** to the section for your topic.
2. Each entry is a link to a dedicated awesome list on that narrower subject —
   follow it for the actual resources.
3. Want to add a list? Read `awesome.md` and `contributing.md` first; the bar
   is deliberately high, and the PR template enforces it.
